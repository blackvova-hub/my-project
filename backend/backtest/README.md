# Тест стратегии

Страница `/backtest` использует существующие React/Vite и Go API. Расчёт выполняется отдельным сервисом `backtest_worker`, не связанным с `workers/alert-engine`.

```text
React Strategy Builder
        ↓ POST /api/backtests
Go API → PostgreSQL backtest_jobs (задание и durable enqueue outbox)
                      ↓ dispatcher
               Redis Stream backtest:jobs:v1
                      ↓ consumer group backtest-workers-v1
                backtest_worker
                      ↓
       общие свечи ClickHouse ← Bybit V5 REST
                      ↓
      PostgreSQL: результат + backtest_trades
                      ↓ GET /api/backtests/{id}
             график, метрики, CSV
```

## Возможности и контракт

- Авторизованный пользователь; отдельная подписка для страницы не требуется.
- Bybit Spot / USDT perpetual Futures: Free — 1 уникальная USDT-пара, Standard — до 5, Pro — до 10.
- На странице доступны **1h и 4h**; завершённый период в пределах последнего календарного года. Старые JSON/черновики с 5m/15m переводятся интерфейсом на 1h с уведомлением при импорте. Общий архив остаётся 5m; `History.Load` агрегирует его. API/движок сохраняют поддержку старых таймфреймов для совместимости сохранённых тестов.
- Long и Short; Spot допускает только Long.
- Новые стратегии используют версию **2**: дерево `and`, `or`, `indicator`, до 32 узлов, до 3 уровней вложенности, до 8 условий в группе. Примеры и Smart Money удалены из конструктора. Старые результаты остаются доступны; простые числовые RSI/MACD-условия импортируются без изменения смысла. Условия прежнего формата, которые нельзя перевести однозначно, требуют повторного выбора индикатора; интерфейс не подменяет их автоматически.
- 17 индикаторов: цена, объём, открытый интерес, CVD, дельта, объём рыночных покупок/продаж, RSI, MACD, EMA, SMA, ATR, стохастик, MFI, OBV, полосы Боллинджера, волатильность. Доступные меры и параметры описаны ниже.
- Сравнения `lt`, `gt`, `lte`, `gte`, `crosses_above`, `crosses_below`. Для процентного изменения пользователь выбирает рост/снижение/любую сторону, положительный порог и окно в часах (1–720, кратно выбранному таймфрейму). «Снижение ≤ 5%» означает снижение от 0 до 5%, а не рост.
- RSI/EMA/SMA/ATR/стохастик/MFI/Bollinger имеют период 2–400 свечей выбранного таймфрейма. MACD использует 12/26/9. У RSI дополнительно доступно изменение в пунктах за окно.
- Результаты движка **2.0.0** включают `signals`: для каждой монеты число доступных проверок входа и совпадений всего дерева. Последняя свеча не создаёт новый вход за границей теста. API сохраняет чтение и исполнение старых контрактов версии 1; новые условия версии 2 принимаются только с 1h/4h.
- Обязательный SL; TP=0 отключает take profit. Дополнительное условие выхода объединяется с защитными выходами через OR.
- Начальный капитал 100–100 000 000 USDT, позиция 0.1–100% капитала, комиссия и проскальзывание 0–5% на каждую сторону сделки.
- Импорт/экспорт полного запроса JSON, сохранение локального черновика по пользователю, история последних 30 задач, отмена, таблица по 20 сделок и полный CSV.

Лимиты конструктора проверяются API по действующему тарифу авторизованного пользователя до создания задания; значение тарифа от клиента не принимается. Неизвестный или отсутствующий тариф считается Free. Вход и выход имеют общий бюджет, TP и SL в него не входят.

| Тариф | Пары | Условия | Группы (включая вход/выход) | Вложенность групп |
| --- | ---: | ---: | ---: | --- |
| Free | 1 | 3 | 2 | Только корневые группы |
| Standard | 5 | 12 | 6 | Корневая + один вложенный уровень |
| Pro | 10 | Общий прежний предел: 32 условия и группы суммарно | В том же бюджете | Корневая + два вложенных уровня |

Free допускает до 3 элементов в группе, Standard/Pro — до 8. Все индикаторы доступны в пределах этих лимитов. Импорт сверх лимита отклоняется; черновики и старые результаты после смены тарифа не обрезаются, но повторный запуск требует подходящего тарифа или уменьшения стратегии. В интерфейсе общий счётчик пар показывает 15, а тарифные ограничения проверяются при добавлении: открывается окно с доступным тарифом. Кнопка «Рандом» заменяет выбранные пары случайными из текущего рынка, сохраняя их количество и исключая дубли (по возможности выбирает полностью новый набор). Единственную пару можно удалить и выбрать другую. В продакшене действуют те же проверки; локальных исключений для тарифов нет.

```json
{
  "requestKey": "2a9c8296-b28f-4dcf-a04a-f12c05827390",
  "exchange": "bybit",
  "market": "linear",
  "symbols": ["BTCUSDT", "ETHUSDT"],
  "timeframe": "1h",
  "from": "2026-08-01T00:00:00Z",
  "to": "2026-09-01T00:00:00Z",
  "strategy": {
    "version": 2,
    "direction": "long",
    "entry": {
      "kind": "and",
      "children": [
        {"kind":"indicator","indicator":"price","measure":"change_pct","direction":"up","windowHours":24,"operator":"gte","threshold":5},
        {"kind":"indicator","indicator":"rsi","measure":"value","period":14,"operator":"lte","threshold":70}
      ]
    },
    "takeProfitPct": 5,
    "stopLossPct": 2,
    "positionSizePct": 20,
    "feePct": 0.1,
    "slippagePct": 0.05,
    "initialCapital": 10000
  }
}
```

`from` включается, `to` исключается; время — UTC, границы кратны таймфрейму. В интерфейсе дата «По» включается целиком. `requestKey` — новый UUID для нового запуска; повтор с тем же ключом возвращает прежний `jobId` для того же пользователя. JSON-файл стратегии не содержит `requestKey`.

API: `POST /api/backtests → 202 {jobId}`, `GET /api/backtests`, `GET /api/backtests/{id}`, `POST /api/backtests/{id}/cancel`, `GET /api/backtests/{id}/trades?page=1`, `GET /api/backtests/{id}/trades.csv`, `GET /api/backtests/symbols?market=spot|linear`. Все операции требуют существующую cookie-сессию; все записи проверяют владельца. Изменения принимаются только как JSON и проверяют Origin / Fetch Metadata.

## Правила исполнения

1. Индикаторы используют только текущую и предыдущие закрытые свечи. EMA имеет SMA seed, RSI использует сглаживание Wilder. Загружается дополнительный прогрев до начала периода: 5× максимальный период + 1 свеча. Пропуск свечи или недостаточный прогрев приводит к понятной ошибке, без подстановки нулевых цен.
2. Первый сигнал формируется внутри выбранного периода; вход и выход по условию происходят на открытии следующей свечи. Не более одной позиции на инструмент, без повторного входа в свечу выхода.
3. Капитал общий. Позиция занимает указанную долю equity на открытии свечи; резервируется номинал и комиссия входа. При нехватке свободных средств позиция уменьшается. Одновременные входы обрабатываются в алфавитном порядке монет, независимо от порядка выбора.
4. Проскальзывание всегда ухудшает цену. Комиссия начисляется на номинал каждой стороны. TP/SL отсчитываются от фактической цены входа. При пересечении обоих уровней внутри свечи выбирается SL; разрыв через уровень исполняется по открытию. Время внутрисвечного выхода обозначает конец свечи, поскольку точное время неизвестно.
5. В конце периода позиции закрываются по close последней свечи с комиссией и проскальзыванием. PnL и win rate — после всех этих затрат.
6. Drawdown считается по полному ряду equity на закрытиях свечей. Sharpe — по дневным доходностям, 365 дней/год, risk-free=0, выборочная дисперсия. При недостаточной истории или нулевой дисперсии Sharpe=null. Profit factor=null при отсутствии убытков (UI показывает ∞, если есть прибыльные сделки, иначе —).
7. График ограничен примерно 1800 точками с сохранением минимумов/максимумов каждого временного блока; метрики считаются до прореживания. Свыше 50 000 сделок задача завершается ошибкой с просьбой сократить период, результат не обрезается незаметно.

Это модель исполнения без плеча. Funding, ликвидации, правила округления лота и тика, минимальный номинал заявки и зависимость рыночного воздействия от размера заявки не моделируются. Эти ограничения видны в разделе «Как считается результат». Каталог содержит текущие торгуемые пары; делистингованные инструменты не доступны, что создаёт survivorship bias для отбора монет.

## Надёжность и общая история

PostgreSQL остаётся источником состояния задачи. Dispatcher публикует queued-записи в отдельный Redis Stream через `FOR UPDATE SKIP LOCKED`; при потере Redis queued-задания публикуются заново. Между XADD и SQL commit возможны повторные доставки, но не потеря задач. Одна активная задача на пользователя ограничивается уникальным partial index; общий лимит — 1000 активных задач. API не скачивает свечи при создании задачи.

Worker захватывает SQL lease с новым UUID, отправляет heartbeat раз в секунду и завершает задачу только с этим UUID. Отмена немедленно отзывает lease; устаревший worker не может записать результат. Через 90 секунд без heartbeat задача возвращается в очередь, максимум три попытки восстановления. Предел выполнения одной попытки — 30 минут. Результат и строки сделок сохраняются в одной транзакции.

ClickHouse хранит закрытые свечи в `shortlong_backtest.candles`, ключ `(market,symbol,timeframe,time)`, месячные партиции, `ReplacingMergeTree` + `FINAL` для безопасных повторных вставок. История общая для всех пользователей. Загрузка заполняет только отсутствующие диапазоны по 1000 свечей. PostgreSQL advisory lock на серию исключает конкурентное скачивание одного диапазона; второй запрос после ожидания перечитывает ClickHouse.

Отдельный `market_history` заполняет общий архив 5m за шесть месяцев для всех текущих USDT Spot/Futures Bybit и обновляет его независимо от запусков бэктеста. Курсоры сохраняются в PostgreSQL, после простоя догружается весь пропущенный промежуток. 15m/1h/4h собираются из полных 5m окон, если готовой старшей серии ещё нет. Redis ограничивает суммарные REST-запросы загрузчика и бэктеста. Подробнее: [архив истории, запуск, статус и подключение других воркеров](HISTORY.md).

## Расчёты индикаторов и их история

| Индикатор | Расчёт / единицы |
| --- | --- |
| Цена | `(close сейчас − close N часов назад) / close N часов назад × 100` |
| Объём | Сумма базового объёма за N часов; изменение суммы относительно предыдущего N-часового окна в % или отношение в разах |
| Открытый интерес | Изменение реального OI Bybit за N часов, только Futures |
| CVD / дельта | Сумма `buy quote volume − sell quote volume` за окно, USDT; либо баланс `(buy − sell) / (buy + sell) × 100`. Изменение CVD и суммарная дельта за одинаковое окно совпадают |
| Покупки / продажи | Сумма соответствующих инициирующих сделок в USDT либо изменение относительно предыдущего окна |
| RSI | Уайлдер, шкала 0–100; либо разница RSI в пунктах за окно |
| MACD | EMA 12 − EMA 26, сигнальная EMA 9; линия/гистограмма в USDT либо пересечение сигнальной линии |
| EMA / SMA | `(close / средняя − 1) × 100`; отрицательное значение — цена ниже средней |
| ATR | ATR Уайлдера / close × 100 |
| Стохастик | Быстрый %K, без сглаживания; положение закрытия в high/low диапазоне периода |
| MFI | Положительный денежный поток / общий поток × 100, типичная цена `(H+L+C)/3` |
| OBV | Изменение OBV / суммарный базовый объём за окно × 100; OBV не заменяет реальную дельту |
| Bollinger | SMA ± 2 стандартных отклонения; %B или ширина полос / SMA × 100 |
| Волатильность | Стандартное отклонение логарифмических доходностей свечей за окно; без годового пересчёта |

`marketdata/indicator_history.go` загружает дополнительные данные **только по задаче**, если индикатор присутствует во входе или выходе. Новых сервисов/очередей нет. История хранится в общей таблице `shortlong_backtest.indicator_history`:

```text
market    symbol   name              time (UTC ms)   value
linear    ADAUSDT  openInterest      timestamp       OI в базовой монете
linear    ADAUSDT  tradeBuyVolume    начало часа     объём покупок в USDT
linear    ADAUSDT  tradeSellVolume   начало часа     объём продаж в USDT
```

Ключ: `(market,symbol,name,time)`, месячные партиции, `ReplacingMergeTree`/`FINAL`. OI берётся из [Bybit V5 open-interest](https://bybit-exchange.github.io/docs/v5/market/open-interest), `intervalTime=1h`. Для свечи используется наблюдение **на её закрытии**; будущее не подставляется. Для 4h потоки суммируются по четырём часам, а OI берётся на правой границе.

CVD и дельта считаются по [официальным публичным архивам сделок Bybit](https://public.bybit.com/): `/trading/SYMBOL/SYMBOLYYYY-MM-DD.csv.gz` для Futures и `/spot/SYMBOL/SYMBOL_YYYY-MM-DD.csv.gz` для Spot. Читаем gzip/CSV потоком, сохраняем только часовые суммы `price × size/volume` по стороне инициатора. Raw-файлы на диск не записываются. Первый длинный тест с этими индикаторами может быть значительно медленнее теста по OHLCV. Готовые дни сохраняются и используются повторно, в том числе после отмены/таймаута (лимит одной попытки — 30 минут).

Advisory lock на `(market,symbol,тип источника)` исключает повторную загрузку одной истории одновременными тестами. Индикаторы имеют независимый прогрев: RSI 400 не заставляет скачивать тысячи дополнительных часов сделок для CVD. Пробелы OI и непубликованный/повреждённый архив завершают задачу явной ошибкой; нулевые потоки допустимы только внутри успешно прочитанного полного дневного архива. Нулевая база процентного изменения и нулевой общий поток для баланса дают недоступное значение, а не бесконечность. В условиях AND/OR неизвестное значение не становится сигналом.

Стакан и ликвидации из live-сканера не включены: архив OHLCV и дневные сделки не содержат исторических снимков этих данных.

## Запуск

Из `backend` для локального стека:

```powershell
docker compose -f compose.yaml -f compose.local.yaml up -d --build --force-recreate backend frontend clickhouse backtest_worker market_history
```

Команда также запускает зависимости PostgreSQL/Redis. Миграция `063_add_backtests.sql` применяется обычным migration runner API. Веб-страница: `http://localhost:3000/backtest`. При запуске существующего локального API его Telegram-настройки по-прежнему берутся из local override.

Production: используются `compose.yaml` и существующий frontend deployment; frontend должен быть пересобран. У ClickHouse отсутствуют host-порты, данные находятся в volume `backtest_candles`. `CLICKHOUSE_PASSWORD` можно задать отдельно; по умолчанию используется обязательный `POSTGRES_PASSWORD`. `BACKTEST_CONCURRENCY=2` (1–8) задаёт число одновременно рассчитываемых задач на один контейнер. Можно масштабировать только новый `backtest_worker`; он не имеет фиксированного `container_name`.

```powershell
docker compose up -d --build backend clickhouse backtest_worker
docker compose logs --tail 100 backtest_worker
docker compose up -d --scale backtest_worker=2 backtest_worker
```

API Docker build использует дополнительный named context `backtest`, уже заданный в Compose. Для отдельной сборки из `backend/api`:

```powershell
docker build --build-context backtest=../backtest -t shortlong-api .
```

Для прямого запуска worker нужны `DATABASE_URL`, `REDIS_ADDR`, `REDIS_PASSWORD`, `CLICKHOUSE_URL`, `CLICKHOUSE_USER`, `CLICKHOUSE_PASSWORD`. ClickHouse database `shortlong_backtest` должна существовать; таблицу worker создаёт сам. `BYBIT_BASE_URL` позволяет указать совместимый endpoint; Compose для worker использует `BACKTEST_BYBIT_BASE_URL`.

## Проверки

```powershell
cd backend/backtest
go test ./...
docker compose -f compose.test.yaml up -d
```

Изолированный стек использует БД `backtest_test` на 25432, Redis на 26379, ClickHouse на 28123. Сначала примените API-миграции к этой БД. Затем:

```powershell
$env:BACKTEST_TEST_DATABASE_URL='postgres://postgres:backtest-test-only@127.0.0.1:25432/backtest_test?sslmode=disable'
$env:BACKTEST_TEST_REDIS_ADDR='127.0.0.1:26379'
$env:BACKTEST_TEST_CLICKHOUSE_URL='http://127.0.0.1:28123'
$env:BACKTEST_TEST_CLICKHOUSE_PASSWORD='backtest-test-only'
go test ./...
```

Интеграционные тесты требуют имя БД с суффиксом `_test`; используйте изолированный стек с остановленным worker, чтобы он не забирал тестовые сообщения. Проверяются admission race, права владельца, отмена/lease fencing, восстановление доставки, атомарная запись результата, дедупликация одновременной загрузки свечей и неполная история. Unit-тесты проверяют экономику и временной порядок исполнения.

Браузерные тесты: `frontend/web/tests/backtest.e2e.spec.ts`, команда `npm run test:backtest`. Нужны запущенные тестовые API и worker, Vite с `VITE_API_BASE=http://127.0.0.1:28080/api` и `VITE_API_BASE_URL=http://127.0.0.1:28080`, разрешённый CORS origin Vite и cookie-сессия тестового пользователя в `BACKTEST_E2E_SESSION`. Значения по умолчанию: Vite 5173, API 28080, браузер Edge; для Chromium задайте `BACKTEST_E2E_CHANNEL=chromium`. API/результаты в этих тестах не подменяются.

Источники протокола: [Bybit Kline](https://bybit-exchange.github.io/docs/v5/market/kline), [Bybit instruments](https://bybit-exchange.github.io/docs/v5/market/instrument), [ClickHouse HTTP](https://clickhouse.com/docs/interfaces/http).
