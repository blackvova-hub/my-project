# Исторически похожие ситуации

`similarity_worker` готовит историю **только по пользовательскому запросу**. Кнопка «Найти похожие» создаёт задачу на выбранные рынок, окно и область поиска. Исходные 5m-свечи остаются в ClickHouse, массовая дозагрузка `market_history` выполняется раз в 12 часов. Недостающие свежие свечи текущего окна выбранной монеты могут догружаться через общий `History.Load` с блокировкой серии и лимитом Bybit. Подготовленные по запросам сигнатуры общие для пользователей и используются повторно.

Внизу окон «Инфо о монете» расположен общий `SimilarityPanel`. Открытие и прокрутка не запускают расчёт. По умолчанию поиск идёт среди истории этой монеты; доступны весь рынок, категория и свой список. После нажатия кнопки показываются прогресс, отмена, затем до шести настоящих графиков (3 × 2 на широком экране). Первый поиск может занимать больше времени. Нажатие на процент раскрывает оценки признаков и последующие исходы.

Над результатами общий переключатель свечей **5м / 15м / 1ч / 4ч**, по умолчанию **1ч**. Выбор сохраняется в браузере. Он меняет только отображение; окно поиска и оценки сходства остаются прежними. Каждую карточку можно независимо двигать, масштабировать и вернуть к исходному виду кнопкой со стрелкой. На телефоне горизонтальное движение управляет графиком, вертикальное сохраняет прокрутку окна.

`GET /api/similarity/jobs/{id}/charts` проверяет владельца завершённой задачи и читает исходные 5m-свечи первых шести совпадений из ClickHouse одним ответом. Это работает и для сохранённых результатов со старым сжатым графиком. Чтение ограничено выбранным окном (до 7 дней) и последующим движением (до 24 часов), всегда до `query.end`. Оно не запускает поиск, индексацию или загрузку с биржи. React Query кэширует ответ; переключение интервалов агрегирует OHLC в браузере без сетевых запросов. Свечи выравниваются по UTC, при разрывах и на границе «Далее» начинается новая свеча: данные будущего не попадают в сравниваемую часть. Свечи на краях участка могут быть неполными.

## Поток данных

```text
Bybit → market_history → ClickHouse candles (единственная копия OHLCV)
                              ↓
Кнопка → authenticated API → similarity_jobs в PostgreSQL
                              ↓
                       similarity_worker
                         ├─ выбранные рынок + окно + область
                         ├─ недостающие Features → Qdrant
                         ├─ 500 кандидатов → ranking → dedup
                         ├─ Future только для найденных совпадений
                         └─ готовый результат задачи + 6 графиков
```

Qdrant хранит только 56-мерную сигнатуру и небольшие метаданные окна; исходные свечи туда не копируются. Для каждого размера окна и версии признаков/весов своя коллекция. Векторы и HNSW размещаются на диске; индексируются `market`, `symbol`, `end`. На маленьких коллекциях Qdrant может выбирать точное сравнение; на больших используется HNSW. Производительность на сотнях миллионов векторов на этой машине не проверена.

## Задачи по запросу

`similarity_streams` содержит курсоры только запрошенной подготовки. Автоматического обхода всей истории нет. Коллекция Qdrant создаётся при первом запросе соответствующего окна. Одна активная задача на пользователя, очередь до 32 задач, по умолчанию один исполнитель. Идентичный активный или завершённый запрос пользователя за последний час возвращает существующий ID. Завершённые задачи старше 7 дней удаляются при создании следующего поиска.

`FOR UPDATE SKIP LOCKED` и token защищают выдачу задач и курсоры. Heartbeat каждые 15 секунд продлевает минутную lease задачи; после сбоя она восстанавливается (максимум три попытки). Штатная остановка возвращает её в очередь. Общий лимит выполнения — 2 часа. Поддиапазоны ограничены семью днями и двумя минутами расчёта. Курсор двигается после успешной записи, повторное исполнение использует те же ID векторов. Неполные участки могут повторяться при следующем подходящем запросе, не раньше чем через час; самостоятельного обхода ремонтов нет.

Исходы считаются после ранжирования только для найденных совпадений, непосредственно из свечей и только до времени запроса. `similarity_outcomes_v1` в рабочем процессе больше не используется. Неполный или ещё не наступивший горизонт не создаёт нулевого исхода.

Без задач worker ждёт уведомления; раз в 30 секунд проверяет только очередь для восстановления после сбоев. Свечи в простое не сканируются. Qdrant ограничен 2 CPU и бюджетом оптимизации 2 CPU, similarity_worker — 1 CPU. После записи Qdrant может завершать внутреннюю оптимизацию уже запрошенных данных.

Браузер проверяет только активную задачу раз в 5 секунд, после завершения или отмены опрос прекращается. В скрытой вкладке опрос отключён. ID сохраняется отдельно для пользователя и монеты: окно можно закрыть и открыть позже. Чужие GET/DELETE задачи возвращают 404; API передаёт проверенный user ID во внутренний сервис.

## Признаки и время

Везде база 5m, время UTC. `end` — исключительная правая граница окна, то есть время закрытия последней входящей свечи. Для окна N нужны N свечей самого окна и N предыдущих свечей опорного режима. Все 2N свечей должны быть непрерывными и валидными. Это также означает, что самые ранние N свечей после начала архива/листинга не могут иметь полного опорного режима.

56 безразмерных признаков разбиты на группы:

- Цена: 16 участков нормализованного пути и 8 участков доходностей.
- Объём: 8 участков относительного объёма, изменение к предыдущему режиму, z-score, всплески, изменение внутри окна.
- Волатильность: относительный true range / ATR, realized volatility и изменения режима.
- Свечи: тело и тени к ATR, доля положительных/неположительных свечей, аномальные диапазоны.
- Статистика: доходность, диапазон, просадка, подъём, положение закрытия, форма движения.

Используется сглаженное ограничение `tanh`, масштабы не обучаются на будущей истории. Абсолютная цена и абсолютный объём не входят в вектор. ATR здесь — средний true range окна в долях цены, а не отдельный индикатор Wilder-14. Внутрисвечная просадка оценивается по OHLC-экстремумам; точный порядок high/low внутри 5m неизвестен.

ANN использует евклидово расстояние с нормировкой групп. Reranking: по каждой группе `100 × exp(-2 × RMS distance)`, итог — взвешенная сумма. Сходство — шкала расстояния, **не вероятность будущего роста**. Trend/volatility/volume regimes возвращаются в metadata; жёсткого фильтра по режиму нет.

Исторический кандидат заканчивается не позже начала текущего окна. Сначала рассчитываются score и dedup, и только затем читаются исходы с `availableAt <= query.end`. Future return, upside/downside и график после события не участвуют в векторе или ранжировании. Пересекающиеся окна одной монеты удаляются. В cross-asset выдаче ограничено число результатов одной монеты и одного временного блока, поэтому результат иногда содержит меньше запрошенного количества.

## Настройки

| Переменная | Значение по умолчанию |
|---|---|
| `SIMILARITY_WINDOWS` | `12:3,36:6,72:12,144:12,288:24,864:72,2016:144` |
| `SIMILARITY_WEIGHTS` | `[0.4,0.2,0.15,0.15,0.1]` |
| `SIMILARITY_CONCURRENCY` | `2` (1–4) |
| `SIMILARITY_CANDIDATES` | `500` (200–1000) |
| `SIMILARITY_HOT_SYMBOLS` | `BTCUSDT,ETHUSDT,SOLUSDT` |
| `QDRANT_API_KEY` | По умолчанию берётся пароль PostgreSQL из окружения, значение не публикуется |

Окна задаются как `число_5m_свечей:шаг_в_5m_свечах`. Например, `288:24` — сутки с шагом 2 часа. Начальные шаги разрежены для локальной машины; `12:1` разрешает каждую 5m свечу для часового окна. Уменьшение шага увеличивает индекс и время подготовки. Горизонты исходов найденных совпадений: 1/3/6/12/24ч, 3/7д. Старые коллекции при смене версии не удаляются автоматически.

Redis объединяет одинаковые запросы между процессами: lock с token на 75 секунд, расчёт до 60 секунд, проверка token при публикации, кэш на 60 секунд. Ключ включает нормализованный запрос, as-of, список разрешённых монет и версию. Ошибки не кэшируются как пустая выдача. На экземпляр ограничено четыре параллельных поиска, на пользователя API — 20 запросов в минуту. Чтение raw OHLCV в request path ограничено текущим окном и графиками выбранных результатов; исторические сигнатуры берутся из индекса.

## Метаданные активов

`similarity_assets`: market, symbol, sectors[], is_alt, is_stablecoin, enabled. Названия секторов не зашиты в ranking. Начальная ручная классификация популярных активов находится в `seed.go`, пример полного импорта — `assets.example.json`; она не претендует на полный справочник. Остальные активы остаются без категории. Для all_crypto/alts/sector/custom stablecoins исключаются по флагу, для same_asset ограничение не применяется. Список известных stablecoins задаёт начальные флаги; оператор может уточнять классификацию.

Импорт проверяется и применяется транзакционно; существующие пользовательские настройки не затираются обычным обновлением каталога:

```powershell
docker compose -f backend/compose.yaml -f backend/compose.local.yaml cp backend/similarity/assets.example.json similarity_worker:/tmp/assets.json
docker compose -f backend/compose.yaml -f backend/compose.local.yaml exec -T similarity_worker /app/similarity -import-assets /tmp/assets.json
```

Cross-market режим в MVP не включён: Spot сравнивается с Spot, Futures с linear. Расширение — в фильтре VectorIndex. Custom universe передаётся явным списком до 100 символов. OI/funding/CVD и прочие признаки, hot-query cache precompute и локальное уточнение соседних timestamps пока не реализованы; интерфейс индекса, версии сигнатур и отдельный Searcher позволяют добавить их отдельно.

## Запуск и контроль

Из корня:

```powershell
.\backend\similarity.ps1 start
.\backend\similarity.ps1 status
.\backend\similarity.ps1 logs
.\backend\history.ps1 status
```

Сервисы имеют `restart: unless-stopped` и volumes. Docker должен быть запущен; после его выключения вычислений нет, после запуска работа продолжается с курсоров. Qdrant и порт 8092 не публикуются на хосте. Общий `production.ps1 start/build` тоже включает новые сервисы.

`status` возвращает `mode: on_demand`. `pending_bars` — оставшиеся интервалы ранее запрошенной подготовки, включая отменённые задачи; наличие pending само по себе не запускает работу. Полнота raw архива проверяется отдельно через `history.ps1 audit`.

API требует обычную сессию сайта:

```text
GET  /api/similarity/options
GET  /api/similarity/status
POST /api/similarity/search
GET  /api/similarity/jobs/{id}
GET  /api/similarity/jobs/{id}/charts
DELETE /api/similarity/jobs/{id}
```

```json
{"market":"linear","symbol":"BTCUSDT","windowBars":288,"scope":"all_crypto","limit":6}
```

В запросе поддерживаются `end` (UTC Unix ms, по умолчанию последняя закрытая 5m), `scope`: same_asset/all_crypto/alts/sector/custom, `sector`, `symbols`, `limit` 1–50. POST отвечает 202 и `jobId`. GET задачи возвращает status, phase, progress, request, error либо result с query/end, matches, score, breakdown, chart и доступными outcomes. DELETE отменяет задачу. Неполная история текущего окна завершает задачу ошибкой.

Для намеренного удаления всех производных данных: отменить активные поиски, остановить similarity_worker, затем выполнить `docker compose -f backend/compose.yaml -f backend/compose.local.yaml run --rm --no-deps -T similarity_worker /app/similarity -purge-derived`. Команда удаляет коллекции similarity_ohlcv, рассчитанные исходы, курсоры, задачи и кеш поиска. Исходные свечи и метаданные монет сохраняются. На старте и при поиске команда автоматически не выполняется.

## Проверки

```powershell
docker compose -f backend/backtest/compose.test.yaml -f backend/similarity/compose.test.yaml up -d
cd backend/similarity
$env:SIMILARITY_TEST_DATABASE_URL='postgres://postgres:backtest-test-only@127.0.0.1:25432/backtest_test?sslmode=disable'
go test ./... -count=1
go vet ./...
```

Тесты используют отдельные PostgreSQL/Redis/ClickHouse/Qdrant и не подключаются к рабочим volumes. Проверяются перенос масштаба цены и объёма, нулевой объём, разрывы, future isolation, horizons, фильтры, dedup, lease fencing, продолжение индекса и реальный pipeline. 40 конкурентных запросов должны вызвать один ANN search. `frontend/web/tests/similarity-live.mjs` проверяет настоящий API и графики в Edge через Playwright.

Документация выбранного индекса: [Qdrant indexing](https://qdrant.tech/documentation/manage-data/indexing/), [query API](https://api.qdrant.tech/api-reference/search/query-points), [collections](https://api.qdrant.tech/api-reference/collections/create-collection).
