## Визуальная сверка

Browser/IAB в среде отсутствовал. Использован Playwright с установленным Microsoft Edge, headless, deviceScaleFactor=1. Скриншоты получены из работающего приложения с настоящими API, PostgreSQL, Redis, ClickHouse и свечами Bybit. Макеты и последние скриншоты обоих состояний открыты через `view_image` в одном проходе проверки. Размеры: 1536 × 1024, 1280 × 900, 390 × 844; мобильный конструктор дополнительно проверен целиком по высоте.

Осознанные отличия от иллюстраций:

- Существующие бренд, ширина шапки, её навигация и кнопка кабинета сохранены. Добавлены ссылка страницы и доступное мобильное меню. Плавающий AI-виджет на этой странице скрыт, чтобы не перекрывать управление тестами.
- Импорт/экспорт JSON, вложенные группы AND/OR и дополнительные условия выхода необходимы для редактирования и сохранения стратегии. Эти действия внесены в спецификацию до реализации. Подсказка периода уточняет годовой лимит и закрытые свечи; подсказка выхода уточняет объединение с TP/SL.
- Bybit — фиксированное значение, а не список несуществующих бирж. Даты зависят от текущего времени. Нативные поля даты/числа локализуются браузером.
- График использует интерактивный lightweight-charts с его атрибуцией, автоматическими делениями шкал и подсказками. На оси слева показано последнее значение; единица USDT указана над графиком.
- Таблица выводит настоящие 20 строк на страницу вместо четырёх демонстрационных строк; поэтому методика находится ниже первого экрана результатов. Она подробно описывает модель исполнения.

Реализация сверена с выбранными макетами с учётом этих явно описанных отличий. Исправляемых существенных визуальных расхождений после повторной проверки не осталось. Тестовые API, worker и Vite остановлены, изолированные Docker-контейнеры и их временные volumes удалены. Автоматическая проверка разрешений отклонила удаление файлов (`blocked by policy`): остались `C:/dev/tmp/backtest-qa`, `C:/dev/tmp/backtest-playwright` и `C:/tmp/backtest-playwright`. Первые две папки внесены в `.gitignore`; они не используются приложением. Исходные макеты и этот журнал сохраняются как документация.

## Функциональные проверки

- Сборка TypeScript/Vite и ESLint всего frontend проходят. Существующие scanner-window и smart-money тесты проходят.
- `go test ./...` для API и backtest, `go vet ./...` для backtest, smoke-тест миграций и Docker-сборки API/worker проходят. Compose production + local корректно объединяется.
- Unit-тесты движка проверяют сигнал на закрытии и вход на следующем открытии, прогрев, RSI/EMA/MACD, пересечения, общий капитал, short, комиссии, проскальзывание, gap, приоритет SL, закрытие периода, метрики, пропуски свечей и отмену. Отдельно проверен объём: год × пять монет × 5m.
- Интеграционные тесты на настоящих PostgreSQL/Redis/ClickHouse проверяют конкуренцию при создании задач, владельца, отмену и устаревший lease, восстановление очереди, атомарное сохранение результата. Четыре одновременных запроса одной истории вызывают одну загрузку диапазона; проверены дедупликация и явная ошибка при пропуске свечи.
- Два Playwright-сценария проходят с настоящими свечами Bybit: конструктор и JSON → создание задачи → перезагрузка → готовый результат → график → пагинация → CSV → мобильная навигация и история; неверный JSON → валидация → запуск → отмена → сохранение отменённого состояния → отказ без авторизации. Подмена API/расчётов не используется.

Браузерный пример для BTCUSDT/ETHUSDT за 30 дней дал 224 сделки. Значения используются только для проверки передачи результатов; прибыльность стратегии не является критерием прохождения теста. Методика и ограничения Futures 1x описаны в [README модуля](../../backend/backtest/README.md).
