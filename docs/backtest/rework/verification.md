# Доработка теста стратегий — 14 сентября 2026

Страница: http://localhost:3000/backtest. Изменённые backend, backtest_worker и frontend собраны и запущены в существующем dev. Новых сервисов для этой доработки не создавалось. Движок результата — 1.1.0.

## Поведение

- Общий Header сайта остаётся в PublicLayout; состояние скрытия при прокрутке сбрасывается при переходе на другую страницу.
- В форме доступны только 1h и 4h. Старые черновики и импортируемые JSON с 5m/15m переводятся на 1h. Импорт сообщает об изменении и предлагает проверить период. Архив общих 5m-свечей и его расписание не менялись. API сохраняет совместимость с прежними таймфреймами.
- Слева в сравнении выбирается индикатор, справа — порог или совместимый индикатор. Сравнение двух констант отклоняется. Старое `30 < RSI` при загрузке превращается в равнозначное `RSI > 30`.
- Операторы `<`, `≤`, `>`, `≥`, пересечения вверх/вниз показаны явно. Под условием есть короткая читаемая запись. В движке сами числовые сравнения уже были корректными; исправлены конструктор, нормализация и объяснение результатов, добавлены регрессионные проверки границ.
- Вложенные группы И / ИЛИ, индикаторы RSI, EMA, SMA, MACD и его линии сохранены. Есть примеры RSI, пересечения EMA и BOS, сброс, импорт и экспорт.
- Smart Money: BOS, CHOCH, MSS, снятие ликвидности, FVG, Order Block; направление сигнала и окно 1–100 свечей. Можно использовать во входе и выходе, объединять с индикаторами через И / ИЛИ.
- В результате видны число проверенных свечей и число совпадений всего условия входа. При нуле совпадений есть объяснение. Ошибка загрузки модуля графика больше не скрывает остальные результаты.

## Функциональная проверка

- `go -C backend/backtest test ./... -count=1`, `go vet ./...` в модуле backtest и тесты API `internal/httpapi/backtest` прошли. Проверены сравнения по обе стороны порога и при равенстве, RSI=0, пересечения, И / ИЛИ, исполнение на следующем открытии, TP/SL, комиссии, проскальзывание, общий капитал и отмена.
- Тесты SMC проверяют подтверждение событий, зеркальную симметрию направлений, отличие снятия ликвидности от пробоя, истечение окна, FVG на третьей свече, вход после подтверждения. Для каждого префикса последовательности проверено, что будущие свечи не меняют уже полученные сигналы.
- `npx tsc -b` и ESLint изменённого frontend прошли. `node --experimental-strip-types --test tests/backtest-model.test.mjs`: 5 тестов прошли, включая старый JSON, запрет двух чисел, нулевой порог и ограничения таймфреймов.
- `backtest.e2e.spec.ts`: 2 сценария прошли против локального dev с настоящими API и worker. В том числе расчёт BTC+ETH, перезагрузка, пагинация, CSV, отмена с сохранением статуса, отказ в доступе к задаче без авторизации.
- `backtest-rework-live.mjs`: 14 групп проверок, 8 завершённых реальных расчётов. Все 6 операторов, SMC BOS Long 1h и SMC FVG Short 4h. Также пары (поиск, лимит 5, удаление), Spot/Short, периоды, каждый индикатор и SMC-переключатель, группы, JSON, история, мобильное меню. Ошибок JavaScript страницы в этом прогоне нет. [Результаты и ID задач](functional-checks.json).
- `backtest-resilience-live.mjs`: 6 групп проверок и ещё 2 реальных расчёта. Все поля капитала/исполнения дошли до worker; выход по индикатору с TP=0 создал 720 сделок; заведомо ложный RSI<0 дал 0 сделок и корректное объяснение. Проверены страницы сделок, раскрытие методики/истории/выхода, пустое поле при экспорте. Отказ загрузки JS графика специально воспроизведён в браузере: метрики и сделки остаются, кнопка обновления восстанавливает график. [Результаты и ID задач](resilience-checks.json).

Для повторения браузерных проверок используются Playwright и установленный Edge. Целевые live-скрипты запускаются из `frontend/web` против локального dev; учётная запись берётся из локального README, сессии не записываются в отчёт. Они добавляют тестовые задачи в историю. Изолированные интеграционные тесты БД без заданного окружения не запускались; связка API → очередь → worker → свечи → результат проверялась реальными задачами dev.

## Точные границы Smart Money

Правила согласованы с существующим `shared/market/smartMoneyEngine.ts`; контракт и параметры описаны в [README движка](../../../backend/backtest/README.md). Swing подтверждается только после пяти последующих свечей. FVG означает образование разрыва, Order Block — подтверждение блока при пробое. Условия ретеста зон не реализованы. Результаты сохранённых тестов прежней версии не пересчитываются автоматически.
