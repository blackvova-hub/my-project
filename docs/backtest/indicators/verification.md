# Конструктор индикаторов — проверка 16.09.2026

Страница: `http://localhost:3000/backtest`. React/Vite, существующий Go API и `backtest_worker`; движок 2.0.0. Новые контейнеры для индикаторов не добавлялись.

## Изменения

- Удалены примеры стратегий и выбор «Индикатор / Smart Money». Один список из 17 индикаторов, 27 вариантов расчёта. Для цены — процент изменения и направление, для RSI — уровень/разница в пунктах, для MACD — линия/гистограмма/пересечение. EMA/SMA сравниваются через отклонение цены от средней в процентах.
- Окно изменения задаётся в часах (1–720), кратных 1h/4h. Период технического индикатора задаётся отдельно в свечах; интерфейс показывает эквивалент в часах. Быстрые окна, вложенные AND/OR, условия выхода сохранены.
- OI берётся из истории Bybit; CVD, дельта, покупки/продажи — из настоящих дневных архивов сделок Spot/Futures. В ClickHouse сохраняются часовые метрики. Загрузка только по задаче, общая для пользователей, без фонового обхода рынка. Подробные формулы и источники: [описание движка](../../../backend/backtest/README.md).
- Исправлены сравнения на границе дробного процентного порога: 0.100 → 0.105 считается ровно 5%, включая `≤` и `≥`. Нулевой порог сохраняется в JSON. Отсутствующий/null-порог и лишние поля отклоняются API.
- Старые однозначные RSI/MACD-условия переводятся при импорте. Непереводимые условия остаются отмеченными для ручной замены; запуск с ними запрещён в новом интерфейсе.

## Проверки

1. `go test ./... -count=1` в `backend/backtest` с отдельными PostgreSQL, Redis и ClickHouse: контракты, все индикаторы/меры, отсутствие влияния будущих свечей, эталонные значения, сравнения/пересечения, единицы 4h-окон, нулевая база, пропуски данных, исполнение, очереди и отмена. Новая интеграционная проверка: три одновременных потребителя делают одну загрузку сделок и одну OI; 4h получает сумму четырёх часов и OI на закрытии. Отдельная проверка пропущенной OI-точки.
2. Парсер обеих CSV-схем Bybit, границы часов, gzip, повреждённые/пустые данные, HTTP 404, отмена, пагинация OI. Отсутствующие данные не заменяются нулями.
3. `go test ./internal/httpapi/backtest/... -count=1` и `go vet ./internal/httpapi/backtest/...` в API.
4. Frontend: TypeScript/Vite production build; ESLint изменённых компонентов; 5 групп model-тестов, охватывающих все 17 индикаторов и меры, JSON, миграцию, окна и ограничения.
5. Playwright/Edge, реальная авторизация и dev-стек: все селекторы/параметры, шесть сравнений, направления, Spot/OI/Short, добавление/удаление/лимит пар, даты, AND/OR, выходы, TP/SL, капитал/затраты, JSON, запуск, перезагрузка, график, CSV, история, отмена и мобильная ширина 390px. [Основной протокол](checks.json): 31 успешный реальный тест, без исключений браузера.
6. После последней пересборки повторены 30 API-сценариев всех вариантов расчёта: [протокол последней сборки](api-checks.json). Проверены Spot CVD, Futures OI+CVD на 4h, Short с выходом по условию и выключенным TP.
7. [Дополнительные проверки](resilience-checks.json): ошибка загрузки чанка графика не скрывает метрики/сделки; обновление восстанавливает график; управление списком с клавиатуры, черновик, сброс, reduced motion, мобильная шапка и результат с нулём сделок.

Тестовые сервисы остановлены после интеграционных проверок. Из пользовательской истории убраны только 60 завершённых задач, созданных этим QA-прогоном; оставлены два результата для просмотра. Прежние пользовательские задачи и рыночные данные не удалялись. Точные идентификаторы: [очистка QA](qa-cleanup.json).
