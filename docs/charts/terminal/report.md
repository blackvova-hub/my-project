## Данные и ограничения

- 84 технических индикатора, 24 панели рыночных данных; до 16 дополнительных классических экземпляров на окно. В каждой панели сохраняются поддерживаемые период/источник, компоненты, цвет/толщина/штрих, уровни, RSI fill, видимость и представление. Неподдерживаемые параметры не обещаются.
- Свечи: публичные REST/WS Bybit и Binance, до 15 000 баров. Повторный REST каждые 30 секунд; деривативы раз в минуту, котировки списка раз в 15 секунд. Общие подписки и in-flight REST с независимой отменой подписчиков; скрытые окна приостановлены. Длинные расчёты выполняет worker.
- OI: исходный шаг 5 минут; базовый актив отдельно от USDT. Funding: фактические выплаты, последние 200 Bybit / 1000 Binance; отсутствие точки на выбранной свече показывается `—`. OI-взвешенный Funding использует обе фактические ставки и оба веса OI в USDT только в общих интервалах. Вес Bybit — OI × index close, Binance — sumOpenInterestValue; это агрегат этих двух бирж.
- CVD — сумма Binance taker delta от первого загруженного бара, до 1000 баров исходного API. Это не тиковой footprint и не CVD всего рынка. Аккаунты и позиции Long/Short различаются. Единственное наблюдение не превращается в OHLC. Пропуски не становятся нулями.
- Heatmap, footprint и large trades сейчас **не подключены и не отображаются как работающие слои**. Доступа к соответствующим историческим данным нет. В интерфейсе перечислены необходимые данные; будущая интеграция потребует провайдера и renderer/фильтров слоя.
- Профиль объёма по свечам остаётся явно обозначенной оценкой. Long/Short — расчёт по пользовательским уровням и размеру, без отправки торговых ордеров.
- JSONB совместима с прежним `/api/chart/config`, миграция схемы не нужна. Workspace сохраняет окна, оформление, шкалы, порядок/высоты, разметку, сравнения, синхронизацию, sidebar и именованные наборы. Лимиты серверного документа: 256 KiB, 50 drawing sets и 100 объектов в наборе. При превышении остаётся локальная копия и JSON export. Устаревшая серверная версия не заменяет свежие изменения; загрузка версии аккаунта создаёт локальную резервную копию.

## Подключаемый контракт orderflow

Серверные переменные: `CHART_ORDERFLOW_PROVIDER_URL` (HTTPS), `CHART_ORDERFLOW_PROVIDER_TOKEN`, `CHART_ORDERFLOW_LAYERS` (comma-separated: `liquidation-heatmap,orderbook-heatmap,footprint,large-trades`). В репозитории нет ключей. Это **внутренний контракт Short & Long**, не выдуманный endpoint CoinGlass: конкретный upstream нужно преобразовать в него на стороне провайдера.

Адаптер вызывает `GET {URL}/v1/charts/{layer}?symbol=BTCUSDT&exchange=binance&market=linear&interval=1h&from=...&to=...`, token передаётся только сервером в `Authorization: Bearer`. Redirect запрещён. Ответ содержит `layer/symbol/exchange/market/unit/source/coverage/updated_at/estimated`, `cells[]` (`time,price_low,price_high,value,buy,sell`) и/или `trades[]` (`id,time,price,quantity,side,exchange`). Время — Unix seconds. Проверяются identity, конечность чисел, границы времени и объём ответа. Для liquidation heatmap обязателен `estimated=true`; фактически наблюдавшиеся ликвидации остаются другим рядом.

Нужно предоставить: уровни потенциальных ликвидаций во времени; историческую глубину стакана по ценам; buy/sell исполнения внутри свечи по ценовым уровням; отдельные крупные исполнения с точным размером/стороной. API приложения: `/api/chart/orderflow/capabilities` и `/api/chart/orderflow/{layer}` под обычной авторизацией. Без источника возвращается 503 с причиной, ошибка провайдера — 502.

## Проверка

На сервере успешно выполнены TypeScript build, ESLint, **86 frontend unit tests**, Vite production build, `go test ./...`, `go vet ./...`. Интеграция API проверена с отдельным PostgreSQL, без тестовых записей в production-БД. Сценарий [terminal-live.mjs](../../../frontend/web/tests/terminal-live.mjs) использует обычный вход, реальные биржевые данные и восстанавливает исходные предпочтения аккаунта в `finally`. Расширенный сценарий выявил и подтвердил исправление follow: просмотр истории/ручной zoom приостанавливают следование, а новый тик не возобновляет его без команды «К рынку». Исправлена ошибка динамической отдельной шкалы сравнения: её видимость применяется ко всему chart runtime, что сохраняет корректные widgets всех панелей.

Браузер: 16 успешных сценариев, 0 ошибок JavaScript, исходные предпочтения аккаунта восстановлены. Сводка: [validation.json](validation.json). Точный перечень браузерных проверок, ошибки и фактические источники: [browser-verification.json](browser-verification.json). Analytics demo использует существующие демонстрационные данные аналитики; replay проверен как доступный маршрут. Для остальных общих потребителей выполнены компиляция и существующие unit-проверки; не заявляется полный ручной проход каждого бизнес-сценария. Проверка offline/online подтверждает сохранность истории/разметки и пригодность интерфейса после восстановления, не длительный стресс-тест биржевых лимитов.

Browser/IAB недоступен в окружении (инвентарь пуст); использован Playwright Chromium **в Docker на сервере**, без запуска локального приложения. ## Сравнение концепта и реализации

Концепт: [concept.png](concept.png), native 1584×992. Итоговый render того же размера: [concept-size.png](concept-size.png). Обе картинки и мобильный render просмотрены через `view_image`, отдельно от функциональных тестов.

| Точка сравнения | Концепт → реализация / причина |
|---|---|
| Композиция | Компактный header/toolbar, левый rail, центральные панели, правый рынок и нижнее управление сохранены; каждый viewport занимает доступную высоту |
| Навигация и текст | Сохранена существующая навигация Short & Long по требованию пользователя; дополнительные разделы проекта остаются. Заголовки реальных источников заменяют выдуманные aggregated подписи концепта |
| Типографика | Явные размеры управляющих элементов и шкал; увеличены легенды, устранены длинные подписи серии, перекрывающие свечи; mobile legends ограничены доступной шириной |
| Палитра и оформление | Существующие Light/Dark/Green tokens, одинаковая геометрия, без декоративных gradients/glow/cards; green соответствует направлению концепта |
| Панели/контейнеры | Плоские панели с разделителями и действиями; порядок/высоты отражают пользовательское рабочее пространство, а не зафиксированную картинку |
| Графические данные | Реальные candles и линии из API; Funding с дискретными выплатами и OI line вместо выдуманных candle/aggregated рядов на картинке. Нет подмены данных ради сходства |
| Mobile | Drawer рынка, перенос toolbar, одна активная панель окна и touch-размеры действий легенды; длинные axis labels убраны |

Концепт реализован в пределах требований существующего приложения и реальных источников. Намеренные отличия: сохранённая навигация проекта, фактические даты/цены/названия источников, пользовательский набор/порядок индикаторов. Сходство с CoinGlass подтверждено на уровне структуры и реализованных механик; полная эквивалентность закрытого продукта не заявляется.
