# Голосовой чат по криптопарам

Страница: `/community/voice`, пункт «Голосовой чат» в меню «Комьюнити» и на странице раздела. Доступ соответствует существующему комьюнити: авторизованный пользователь с PRO.

Один каталог объединяет пары Binance, Bybit, OKX, Bitget, Gate.io и KuCoin. Ключ — базовая и котируемая валюта, например `BTC-USDT`; биржа, спот, бессрочный или срочный контракт не создают дубликаты. `BTC-USDC` остаётся отдельной парой. Контрактные множители `1000PEPE` и `PEPE` объединены. Списки получают с публичных API, включая пагинацию Bybit. При частичном отказе сохраняются доступные рынки и последние полученные пары; интерфейс показывает неполное покрытие. Каталог обновляется раз в 30 минут, при отказах — через 2 минуты. Серверный кеш переживает перезапуск; записи старше суток не восстанавливаются.

Каталог **не создаёт комнаты**. Ни просмотр пар, ни выдача токена не вызывают `CreateRoom`. LiveKit создаёт `pair-BTC-USDT` при фактическом подключении первого клиента. `departure_timeout: 1` удаляет её спустя секунду после выхода последнего; комнаты с нулём участников сразу исключаются из API занятого списка. Незавершённая попытка входа очищается через `empty_timeout: 1`. Лимит — 50 участников в комнате.

При входе микрофон выключен. Доступны включение микрофона, заглушение входящего звука, громкость, выбор устройств, список участников и индикация речи. Заглушение входящего звука также выключает микрофон; включение звука его автоматически не включает. При переключении комнаты старое соединение закрывается. Уход со страницы завершает соединение и освобождает устройства. Потерю связи SDK пытается восстановить; при окончательном отключении интерфейс предлагает повторный вход. При входе того же аккаунта в ту же комнату с другого устройства предыдущий клиент получает объяснение отключения.

## Развёртывание в локальной сети

Адрес: [голосовой чат на server01](https://192.168.0.130/community/voice).

LiveKit `v1.13.9`, браузерный SDK `2.22.4`, серверный Go SDK `v2.19.0`. Go SDK требует Go `1.26.8`; зависимости зафиксированы в `go.mod`/`go.sum` и npm lockfile. Образы Caddy и LiveKit также закреплены по версии.

Параметры LAN находятся в `backend/deploy/server/compose.voice.yaml`, `voice.Caddyfile`, `setup-voice.py`. `compose.sh` подключает voice override после создания `/var/lib/shortlong/voice/livekit.yaml`.

На уже работающем server01:

```sh
sudo python3 /opt/shortlong/backend/deploy/server/setup-voice.py
sudo /opt/shortlong/backend/deploy/server/compose.sh up -d --no-build --no-deps livekit voice_https
# После получения Caddy root.crt повторить setup: только публичный CRT станет
# доступным для nginx. Приватные ключи сохраняют закрытые права.
sudo python3 /opt/shortlong/backend/deploy/server/setup-voice.py
sudo /opt/shortlong/backend/deploy/server/compose.sh up -d --no-build --no-deps backend frontend
```

Ключи генерируются на сервере и остаются в приватной `.env` и конфигурации LiveKit с правами `0600`; в браузер попадает только пятиминутный токен для конкретного пользователя/комнаты. Разрешена публикация только микрофона, подписка на аудио; камера, экран, передача данных и административные права не выдаются. API проверяет сессию, подписку, JSON, известную пару и Origin. Управление комнатами закрыто на HTTPS-прокси; `/livekit/rtc` и подмаршруты проксируют только клиентский сигналинг.

LiveKit использует host networking, LAN IP `192.168.0.130`, UDP `7882` и резервный WebRTC TCP `7881`. Его административный HTTP `7880` слушает только loopback и Docker bridge. HTTPS `443` опубликован на LAN IP. TURN для подключения через интернет в этом LAN-развёртывании не настроен. Для публичного доступа нужны домен, сертификат публичного CA, корректные внешние ICE адреса/порты и при необходимости TURN; это отдельная конфигурация.

Caddy выдаёт и обновляет локальный TLS-сертификат. Его публичный корневой сертификат доступен по `/voice-local-ca.crt` как по HTTP, так и по HTTPS. Приватные ключи не раздаются. На клиентском устройстве требуется доверие этому CA; сертификат не устанавливается автоматически кодом приложения.

SHA-256 отпечаток корневого сертификата установленного LAN сервера:

```text
487A2D2368EB6015A5C0935227A70A6154F2A98A19EB2CB34F9AA9D13E43D6E1
```

Установка сертификата на пользовательский ПК **отложена по просьбе пользователя**; дальнейшие действия отмечены в [TODO.md](TODO.md).

Windows: скачать сертификат, проверить отпечаток DER-сертификата, открыть мастер установки для текущего пользователя и выбрать «Доверенные корневые центры сертификации». После установки открыть HTTPS-адрес. В браузерах с отдельным хранилищем доверия может потребоваться импорт в настройки сертификатов браузера. Порт HTTP остаётся доступен для существующих страниц; голосовой экран по HTTP объясняет переход на HTTPS.

## Проверка

Все сборки, тесты и браузеры запускались **на сервере**. Локально приложение не запускалось. Встроенный Browser/IAB не предоставлял доступного браузера; использован Playwright в серверном Docker, обычный Chromium в режиме headless. Облегчённый `chromium-headless-shell` не поддержал захват аудио в этом окружении, поэтому для медиа используется `channel: chromium`.

`tests/voice-live.mjs` использует два реальных аккаунта и настоящий self-hosted LiveKit. Тестовый второй аккаунт создаётся только на время проверки и удаляется в `trap`. Fake audio hardware подаёт WAV через настоящий `getUserMedia`; токены, каталог, WebSocket, ICE, Opus-публикация и подписка не подменяются. Web Audio измеряет RMS декодированного удалённого `MediaStream` на втором клиенте. Тест также проверяет индикатор речи, клавиатурное изменение громкости, deafen, смену комнаты, отказ разрешения микрофона, cleanup при навигации и мобильный экран.

Параметры браузерного теста: `VOICE_E2E_BASE`, `VOICE_E2E_ACCESS_FILE`, `VOICE_E2E_SECOND_EMAIL`, `VOICE_E2E_AUDIO_FILE`, `VOICE_E2E_OUTPUT`. Файлы с паролями/сессиями не входят в репозиторий. В автоматизированном браузере используется `ignoreHTTPSErrors` для локального CA; отдельно HTTPS проверен `curl --cacert` с настоящим корневым сертификатом. На пользовательском устройстве нужно доверие к CA.

Результаты и изображения: `verification.json`, `dark.png`, `light.png`, `green.png`, `connected.png`, `mobile.png`. Пустота физического списка комнат дополнительно проверена приватным RoomService API после завершения браузеров. HTTP API занятости само по себе не служит доказательством физического удаления, поскольку скрывает нулевую занятость.

## Визуальная сверка

Макет `concept.png` создан встроенным ImageGen: полный экран сообщества, поиск/каталог слева, выбранная пара и вход справа, устройства звука снизу. Реализация сверена с макетом при одинаковом viewport `1536 × 1024` и проверена в Light, Dark, Green, с hover/focus, а также на ширине 390 px.

| Область | Сверка |
| --- | --- |
| Иерархия | Breadcrumb → заголовок → краткое описание → рабочая область; заголовок 28 px, заголовок пары/пустого состояния 22 px. |
| Компоновка | Единая область с боковой колонкой 300 px, разделителем и гибкой панелью комнаты. |
| Список | Поиск, две вкладки, выделение выбранной пары, общий скролл вместо тысяч DOM-элементов; доступное «Показать ещё». |
| Вход | Центральные наушники, объяснение выключенного микрофона, один основной CTA. |
| Управление звуком | Нижняя зона с пояснением, двумя устройствами и громкостью; активные кнопки разговора добавляются после входа. |
| Состояния | Никаких выдуманных участников/чисел; реальные участники, ошибки, неполный каталог, пустой занятый список. |
| Адаптивность | На телефоне каталог над комнатой, ограниченный скролл пар, устройства в одну колонку; горизонтального скролла нет. |

Осознанные отклонения от сгенерированного макета обусловлены существующим проектом: сохранён настоящий Header/Footer, ширина содержимого 1200 px, семантические зелёные акценты вместо придуманного генератором синего. Три темы используют одинаковую геометрию. Декоративные текстуры/градиенты генератора не перенесены согласно `frontend/AGENTS.md`. Текст под парой уточняет жизненный цикл комнат по последней правке пользователя.

## Откат

Образы до этой задачи сохранены как `shortlong-frontend:pre-community-voice-20261013` и `shortlong-backend:pre-community-voice-20261013`. Изменённые исходники и прежний `compose.sh` сохранены в `/opt/shortlong/releases/pre-community-voice-20261013`. Чтобы откатить приложение, вернуть теги `latest` на эти образы, восстановить прежний `compose.sh` и исходники из резервной копии, затем пересоздать только backend/frontend. Контейнеры `shortlong_livekit` и `shortlong_voice_https` можно остановить отдельно. Базы и остальные сервисы не изменять; сертификаты и ключи сохранять в приватном каталоге сервера.
